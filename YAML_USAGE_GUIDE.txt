================================================================================
Spring Boot 101 - YAML 配置文件使用指南
================================================================================

本指南说明如何使用项目中的各个 YAML 配置文件

================================================================================
1. 配置文件对比与选择
================================================================================

项目提供了以下配置文件：

文件名                          | 适用场景                | 数据库配置          | 推荐用途
------------------------------ | ----------------------- | ------------------- | --------
application.yml                | 通用/默认              | MySQL+MongoDB(可选) | 开发和演示
application-h2.yml             | 开发/测试              | H2 内存数据库       | 快速测试，无需安装DB
application-mysql.yml          | 生产环境               | MySQL 仅            | 生产部署
application-mongodb.yml        | 过渡/原始环境          | MongoDB 仅          | 迁移前的原始环境
application-migration.yml      | 数据迁移               | MySQL + MongoDB     | MongoDB→MySQL 迁移

================================================================================
2. 快速开始 - 5分钟启动
================================================================================

方式一：使用 H2（无需安装数据库）
---
  mvn clean spring-boot:run -Dspring.profiles.active=h2

  然后访问：
  - API: http://localhost:8080/api/orders/health
  - H2 Console: http://localhost:8080/h2-console

  H2 Console 登录信息：
  - JDBC URL: jdbc:h2:mem:testdb
  - User Name: sa
  - Password: (留空)

方式二：使用默认配置（application.yml）
---
  mvn clean spring-boot:run

  注意：需要确保 MySQL 在 localhost:3306 运行
  或编辑 application.yml 修改数据库连接信息

================================================================================
3. Spring Profiles 激活方式
================================================================================

方式一：Maven 命令行
---
  mvn spring-boot:run -Dspring.profiles.active=h2
  mvn spring-boot:run -Dspring.profiles.active=mysql
  mvn spring-boot:run -Dspring.profiles.active=mongodb
  mvn spring-boot:run -Dspring.profiles.active=migration

方式二：IDE 配置（IntelliJ IDEA）
---
  1. Run → Edit Configurations...
  2. 在 "VM options" 中添加：
     -Dspring.profiles.active=h2
  3. 点击 "Run" 启动

方式三：环境变量
---
  export SPRING_PROFILES_ACTIVE=h2
  mvn spring-boot:run

方式四：JAR 运行
---
  mvn clean package
  java -jar target/spring-boot-101-1.0.0.jar --spring.profiles.active=h2

方式五：application.yml 指定
---
  spring:
    profiles:
      active: h2

================================================================================
4. 各配置文件详细说明
================================================================================

4.1 application.yml（默认/通用配置）
---
  用途：开发、演示、默认启动
  特点：
    - MySQL 为主数据源
    - 支持可选 MongoDB 配置
    - 平衡的性能和功能配置
    - 日志级别为 DEBUG，便于开发调试

  何时使用：
    - 本地开发
    - 演示 API
    - 学习项目

4.2 application-h2.yml（H2 内存数据库）
---
  用途：快速测试、无依赖环境
  特点：
    - 使用 H2 内存数据库
    - 无需安装任何数据库
    - 每次启动自动建表（create-drop）
    - 关闭后数据丢失
    - 提供 H2 Web 控制台

  何时使用：
    - 快速验证功能
    - 初学者学习
    - 编写单元测试
    - 没有 MySQL/MongoDB 环境

  优势：
    ✓ 开箱即用，无依赖
    ✓ 启动快速
    ✓ 数据隔离，不污染真实数据库
    ✓ 提供 Web 控制台查看数据

  劣势：
    ✗ 应用关闭后数据丢失
    ✗ 某些 MySQL 特定功能可能不支持
    ✗ 不适合大量数据测试

4.3 application-mysql.yml（MySQL 生产配置）
---
  用途：生产环境部署
  特点：
    - MySQL 仅，禁用 MongoDB 和 JPA
    - 连接池优化（30-40 连接）
    - 日志级别为 WARN，性能最优
    - Hibernate ddl-auto 为 validate，防止意外修改表结构
    - 启用 Prometheus metrics
    - Gzip 压缩启用

  何时使用：
    - 生产环境部署
    - 性能测试
    - 并发测试

  注意事项：
    ⚠ 需要提前创建数据库和表
    ⚠ 修改用户名和密码为真实值
    ⚠ 配置连接池大小根据服务器资源调整
    ⚠ 启用了查询日志，根据需要调整

  配置修改示例：
    spring:
      datasource:
        url: jdbc:mysql://your-host:3306/your-db
        username: your-user
        password: your-password

4.4 application-mongodb.yml（MongoDB 原始环境）
---
  用途：使用 MongoDB 的原始环境
  特点：
    - MongoDB 仅
    - 禁用 MySQL 和 JPA
    - 自动创建索引
    - 连接池优化

  何时使用：
    - 迁移前的原始环境
    - 测试 MongoDB 功能

  MongoDB 连接修改：
    spring:
      data:
        mongodb:
          uri: mongodb://user:password@your-host:27017/your-db
          database: your-db

4.5 application-migration.yml（迁移环境）
---
  用途：MongoDB→MySQL 的迁移过程
  特点：
    - 启用双数据源（datasource.enable-migration: true）
    - MySQL 和 MongoDB 同时运行
    - 连接池更大（MySQL: 40，适应迁移并发）
    - Batch size 更大（100），提高迁移速度
    - 迁移日志详细（DEBUG 级别）
    - 单独的迁移日志文件

  何时使用：
    - MongoDB 到 MySQL 的数据迁移
    - 测试迁移逻辑
    - 灰度迁移验证

  迁移流程：
    1. mvn spring-boot:run -Dspring.profiles.active=migration
    2. 调用迁移 API：
       - GET  /api/orders/migration/progress
       - POST /api/orders/migration/migrate-by-customer/{id}
       - POST /api/orders/migration/migrate-all
       - GET  /api/orders/migration/validate
    3. 验证数据一致性
    4. 切换到 application-mysql.yml
    5. 监控应用运行

5. 常见配置修改
================================================================================

5.1 修改数据库连接
---
  MySQL:
    spring:
      datasource:
        url: jdbc:mysql://localhost:3306/spring_boot_101
        username: root
        password: '123456'

  MongoDB:
    spring:
      data:
        mongodb:
          uri: mongodb://localhost:27017/spring_boot_101
          database: spring_boot_101

5.2 修改端口
---
  server:
    port: 9090

5.3 修改日志级别
---
  logging:
    level:
      com.example.springboot: DEBUG    # 项目日志
      org.springframework: WARN         # Spring 日志
      org.hibernate: WARN              # Hibernate 日志

5.4 修改连接池大小
---
  spring:
    datasource:
      hikari:
        maximum-pool-size: 50    # 最大连接数
        minimum-idle: 10         # 最小空闲连接数

5.5 修改日志输出位置
---
  logging:
    file:
      name: /var/log/spring-boot-101/app.log
      max-size: 100MB
      max-history: 30

5.6 修改 Batch Size（迁移性能）
---
  spring:
    jpa:
      properties:
        hibernate:
          jdbc:
            batch_size: 200  # 增大批量大小

6. YAML 与 Properties 格式对比
================================================================================

Properties 格式：
---
  spring.datasource.url=jdbc:mysql://localhost:3306/db
  spring.datasource.username=root
  spring.datasource.password=123456
  spring.jpa.hibernate.ddl-auto=update

YAML 格式：
---
  spring:
    datasource:
      url: jdbc:mysql://localhost:3306/db
      username: root
      password: '123456'
    jpa:
      hibernate:
        ddl-auto: update

优势对比：
  YAML:
    ✓ 结构清晰，层级明显
    ✓ 易于阅读和维护
    ✓ 支持复杂数据结构
    ✓ 缩进表示层级关系

  Properties:
    ✓ 简洁，行数少
    ✓ 兼容性强
    ✓ 不需要理解缩进规则

7. 调试技巧
================================================================================

7.1 查看当前活跃的 Profile
---
  应用启动日志会显示：
  The following profiles are active: h2,mysql

7.2 查看配置属性值
---
  添加到应用中：
    @ConfigurationProperties
    public class AppProperties {
        @Value("${spring.datasource.url}")
        private String datasourceUrl;

        // getter/setter
    }

7.3 配置验证
---
  使用 @Validated 和 @NotNull 等注解验证配置

7.4 环境特定日志
---
  logging:
    level:
      com.example.springboot: DEBUG

  然后在代码中：
    log.debug("当前配置: {}", datasourceUrl);

8. 性能调优建议
================================================================================

开发环境（h2）：
---
  spring.jpa.show-sql: true          # 显示 SQL
  logging.level.root: DEBUG          # 调试日志
  spring.datasource.hikari.maximum-pool-size: 10

测试环境（mysql）：
---
  spring.jpa.show-sql: false         # 关闭 SQL 显示
  logging.level.root: INFO           # 信息日志
  spring.datasource.hikari.maximum-pool-size: 20
  spring.jpa.properties.hibernate.jdbc.batch_size: 50

生产环境（mysql）：
---
  spring.jpa.show-sql: false         # 绝对不显示
  logging.level.root: WARN           # 仅警告及以上
  spring.datasource.hikari.maximum-pool-size: 30-50
  spring.jpa.properties.hibernate.jdbc.batch_size: 100
  server.compression.enabled: true   # 启用压缩

迁移环境（migration）：
---
  spring.datasource.hikari.maximum-pool-size: 40
  spring.jpa.properties.hibernate.jdbc.batch_size: 100
  logging.level.com.example.springboot.service.MigrationService: DEBUG

9. 故障排除
================================================================================

问题1：应用启动失败，显示"Could not get a resource from the pool"
原因：数据库连接失败或连接池溢出
解决：
  1. 检查数据库是否运行
  2. 检查连接字符串是否正确
  3. 减小 maximum-pool-size
  4. 检查防火墙设置

问题2：配置文件未被读取
原因：Profile 激活不正确
解决：
  1. 检查 Profile 名称是否正确
  2. 确认使用 -Dspring.profiles.active=name 启动
  3. 查看启动日志中的 "The following profiles are active"

问题3：MySQL 和 MongoDB 配置冲突
原因：两个数据源配置同时启用且 enable-migration=false
解决：
  1. 检查 datasource.enable-migration 设置
  2. 确认只启用需要的数据源
  3. 使用不同的 Profile 隔离配置

问题4：H2 数据库中看不到表
原因：ddl-auto: create-drop 自动删除表
解决：
  - 这是正常行为，每次启动都是新的数据库
  - 不要关闭应用，数据会丢失

问题5：迁移性能缓慢
原因：batch_size 过小或连接池过小
解决：
  1. 增大 batch_size 到 100-200
  2. 增大 maximum-pool-size 到 40-60
  3. 关闭 show-sql 和详细日志

12. 最佳实践
================================================================================

✓ 使用 Profile 隔离配置
  - 每个环境一个独立的配置文件
  - 敏感信息（密码）从环境变量读取

✓ 定期验证配置
  - 启动时检查 Profile 是否正确激活
  - 查看启动日志确认数据库连接

✓ 记录配置更改
  - 修改配置后测试功能
  - 记录性能变化

✓ 备份原始配置
  - 保留 application.properties
  - 重要配置版本控制

✓ 使用配置优先级
  1. 命令行参数 (--spring.datasource.url=...)
  2. 环境变量 (SPRING_DATASOURCE_URL)
  3. application.properties / application.yml
  4. application-{profile}.properties / .yml
